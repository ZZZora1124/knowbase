# 大脑操作 — 环境上下文层

大脑不是档案馆，而是每次交互双向流过的活体上下文膜。

## 契约

本 skill 保证：
- 任何外部 API 调用前先查大脑（脑优先查找）
- 每条入站信号触发读取→丰富→写入循环
- 每条出站响应前检查大脑的相关上下文
- 每条写入事实都有来源归因（内联 `[来源：...]` 引用）
- 用户直接陈述是最高权威数据
- 每次 brain 写入后强制维护反向链接（铁律）

## 铁律：反向链接（强制）

每次提及有 brain 页面的人物或公司，必须从该实体页面创建指向提及页面的反向链接。
未链接的提及 = 残缺的大脑。

## 各阶段

### 阶段 1：脑优先查找（强制）

在使用任何外部 API 查询人物、公司或话题之前：

1. `knowbase brain search "名称" --timeout 15` — 关键词搜索已有页面
2. `knowbase brain query "关于名称的自然语言问题" --timeout 15` — 混合搜索获取上下文
3. `knowbase brain get <slug> --timeout 10` — 知道 slug 时直接读取完整页面
4. 检查反向链接：哪些页面引用了该实体？`knowbase brain backlinks <slug> --timeout 10`
5. 检查时间线：该实体近期发生了什么？

大脑几乎总有相关内容。外部 API 用于填补空白，而不是从头开始。

### 阶段 2：每条入站信号（读取→丰富→写入）

每条提及人物或公司的消息、会议、邮件或对话：

1. **检测实体** — 提及的人物、公司、项目
2. **加载 brain 页面** — 响应前读取现有页面获取上下文
3. **识别新信息** — 本次信号告诉我们页面尚不知道的什么？
4. **写回大脑** — 用新信息 + 时间线条目 + 来源引用更新 brain 页面
5. **不存在则创建** — 若值得记录且无页面，通过丰富创建

**用户直接陈述是最高价值数据源。** 立即写入 brain 页面并标注
`[来源：用户，YYYY-MM-DD]`。

### 阶段 2.5：结构化图谱更新（自动）

每次 `put_page` 调用自动提取实体引用并写入图谱（links 表），推断关系类型。
页面文本中不再有的引用（过期链接）在同一次调用中删除。

- 普通页面写入无需手动调用链接命令。
- 推断的链接类型：`attended`（会议→人）、`works_at`、`invested_in`、
  `founded`、`advises`、`source`（frontmatter）、`mentions`（默认）。
- `put_page` 响应包含 `auto_links: { created, removed, errors }`，可验证结果。
- 含具体日期的时间线条目仍需显式调用 `knowbase brain timeline-add <slug> <date> "<摘要>" --timeout 15`。

### 阶段 3：每条出站响应（读取→拉取→响应）

回答关于人物、公司或话题的问题前：

1. **检查大脑** — 读取相关页面
2. **拉取上下文** — 使用 compiled_truth + 近期时间线
3. **带上下文响应** — 大脑让每个答案更好

有 brain 页面时不要单纯依赖通用知识回答。

### 阶段 4：环境丰富

这不是特殊模式，而是默认行为。用户说的每件事都是一个摄入事件。

- 提及人物 → 检查大脑，需要时创建/丰富（后台进行）
- 提及公司 → 同上
- 分享链接 → 摄入（委托给 idea-ingest，MVP 阶段可跳过）

**规则：**
- 永不为了丰富而打断对话
- 任何会拖慢响应的操作都在后台完成
- 不要宣告"我正在丰富大脑"——静默执行

## 输出格式

无单独输出。brain-ops 是常驻行为层，不是报告生成器。
输出是更新的 brain 页面和更丰富的响应。

## 来源归因格式

每条引用必须包含来源：`[来源：slug]`。例如：

> 你告诉我关于重试预算方法的事 — 参见 [来源：topics/resilience]。

规则：
- 引用 `sources.id`（不可变），不用 `sources.name`（可变展示名）。
- 每个 `search`、`query`、`get_page` 返回的页面都携带 `source_id`，引用时始终使用。

## 反模式

- 不查大脑就回答关于人物/公司的问题
- 先用外部 API 再查大脑
- 写入事实时不加内联 `[来源：...]` 引用
- 阻塞响应去做丰富
- 用权威性更低的来源覆盖用户直接陈述
- 为不值得记录的实体创建 brain 页面
